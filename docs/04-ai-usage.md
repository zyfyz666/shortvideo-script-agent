# 04 AI 工具使用说明

## 使用声明

本项目在开发过程中使用了 AI 编程助手（opencode CLI + DeepSeek 模型）辅助完成部分工程实现工作。以下如实说明使用范围、方式与本人贡献。

## AI 参与的部分

| 环节 | AI 参与程度 | 说明 |
| --- | --- | --- |
| 方案设计 | 辅助讨论 | 与 AI 讨论了"框架 vs 原生实现""Mock + 真实双模型""防虚报机制""时长估算模型"等选型，最终方案由本人确认 |
| 代码实现 | 辅助生成 | 工具层 / Agent 循环 / LLM 客户端 / CLI 等代码由 AI 起草，本人逐文件审阅、修正 |
| 测试编写 | 辅助起草 | 测试用例（验收点映射、边界断言）由本人确定，代码由 AI 起草 |
| 文档撰写 | 辅助起草 | 由 AI 起草初稿，本人核对与题目要求的符合性后定稿 |
| 验收证据 | 辅助生成 | Mock 与真实模型的 `traces/`、`outputs/` 由脚本生成，本人核对结果 |

## 本人独立完成的部分

- 题目理解、验收点拆解、输入/输出字段与状态语义约定；
- 关键设计决策：结论由工具观察推导的防虚报机制、时长硬约束闭环、事实接地规则（R2/R3）、失败路径显式建模；
- 对 AI 产出代码的审查与缺陷修复（见下）；
- 真实模型与 Mock 全部运行结果的验证与验收核对。

## AI 产出代码中发现并修复的问题（示例）

1. **外部 shell 残留密钥导致 401**：运行环境里有一个过期的 `OPENAI_API_KEY`，真实模型调用返回 401。定位后改为**项目 `.env` 优先于外部环境变量**（`src/config.js` 的 `loadDotEnv`），保证按仓库内配置可复现；并在文中说明。
2. **网关限流 429**：真实 API 偶发 `429 Too Many Requests`。`_chat` 的重试策略改为最多 4 次**指数退避**（并尊重 `Retry-After`）。
3. **网关不支持 `response_format`**：部分 OpenAI 兼容网关对 `response_format:{type:"json_object"}` 返回 400；改为 400 时去掉该字段再试一次。
4. **真实模型编造卖点**：一次真实运行中模型写出素材里没有的"一周充一次电"。修复为**双保险**：系统提示明确"严禁编造"，同时在工具层用 R2/R3 把无素材支撑的事实/效果判为违规——即使模型写了也会被 `check_rules` 拦下。真模型复跑时自行删除了该表述。
5. **Node 22 下 `node --test tests/` 把目录当模块**：安装脚本一度报 `Cannot find module ...\tests`。改为 `node --test`（自动发现 `*.test.js`）后 17 项正常执行。

> 这也是本项目"AI 使用边界"的体现：AI 产出必须经人工审查与测试验证，不能直接信任。
