# 05 复盘与改进方向

## 做得好的地方

1. **"结论由工具观察推导"是本项目最有价值的决策**。让模型只输出"选哪个动作 + 参数"，时长是否达标、是否有风险、素材来源，全部由 `estimate_duration` / `check_rules` 的观察结果决定（`_buildResult`）。这样"编造卖点""谎报达标"没有藏身之处——不是靠提示词求模型别撒谎，而是让谎话进不了结果结构。
2. **时长闭环真正体现了 ReAct**：初稿超长 → 观察 `within_target=false` → 压缩 → 再估算达标，而不是"一次生成碰运气"。
3. **Mock / 真实双路径**让全部验收点离线可复现、断言确定，同时用真模型验证流程普适。05 用例尤其说明问题：真模型能压到 4.8s、Mock 压不到 5s，两条路径各自证明了"框架正确"和"模型能力"。
4. **失败路径显式建模**：工具故障、预算耗尽、缺信息、无素材、超时长都有明确状态与原因字段，而不是笼统的 error。

## 遇到的坑

| 问题 | 根因 | 处理 |
| --- | --- | --- |
| 真实模型 401 | 外部 shell 残留过期 `OPENAI_API_KEY` | 项目 `.env` 优先于外部环境 |
| 网关 429 限流 | 偶发限流 + 重试不足 | 指数退避重试（最多 4 次，尊重 `Retry-After`） |
| 真实模型编造卖点（"一周充一次电"） | 模型自由发挥 | 系统提示 + 工具层 R2/R3 双保险拦截 |
| 网关 400（response_format） | 兼容网关不支持该字段 | 400 时去掉字段重试一次 |
| `node --test tests/` 报找不到模块 | Node 22 下目录参数被当模块 | 改用 `node --test` 自动发现 |
| 非 ASCII 路径 + 目录被移动 | 工作目录在 `D:\脚本\...`，且被外部归档 | 固定路径并建立 ASCII junction 作为稳定工作入口 |

## 已知限制

1. **时长估算为线性近似**：固定 `4.2 字/秒` + 每分镜 `0.5s` 开销，未考虑语气停顿、配乐、画面停留。它是"硬约束的可计算代理"，真实成片仍需人工校对。
2. **检索是 bigram 模糊匹配，非语义**：同义词/近义表达召回弱（例如"台灯"能召回，"照明设备"不能）。素材量大时应换向量检索。
3. **MockLlm 是策略脚本不是模型**：它验证的是 Agent 框架的正确性，不能证明真实模型永远遵守边界；真实路径目前只在 5 个场景验证过。
4. **无多轮澄清闭环**：`needs_input` 之后需要用户重新发起一次任务，Agent 不保留跨轮上下文。
5. **无并发/持久化概念**：脚本结果只写文件，无数据库、无并发控制。

## 如果继续迭代

1. **语义检索**：为素材建 embedding，替换 bigram 打分；同义词/多模态（图文素材）一并考虑。
2. **多轮澄清闭环**：`needs_input` 返回结构化待补字段，用户补齐后带上下文续跑同一会话。
3. **结构化评测集 + CI**：把 examples 断言固化为独立 JSON 断言脚本（现已内置于 `run-examples.js --check`），接入 CI 每次提交自动跑。
4. **真实模型回归**：对关键验收点用真模型固定 temperature=0 跑回归，观察提示词改动的影响。
5. **可观测性**：统计每次运行的 token 消耗、工具耗时，便于成本评估与限流治理。

## 一点感受

Agent 的难点不在"让模型动起来"，而在**让失败可见、让边界不可绕过**：时长硬约束、事实接地、预算上限、结论由观察推导，这些机制比提示词更可靠。真模型测试是必须的——它会走出 Mock 想不到的路径（比如把 5 秒脚本压到 4.8 秒），逼你把"成功/失败"的判定交给工具而不是模型的一句话。
